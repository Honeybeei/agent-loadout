# Writing Rules

Read this document before writing or editing code or documentation. It owns common language, documentation style, and prose-wrapping rules, not a technology-specific coding style or the structure of a particular document type.

## Language

- Write code, comments, documents, and natural-language metadata values in English.
- Preserve non-English literal content when its exact form is needed for behavior, tests, localization, example data, or faithful quotation. Write the surrounding explanations in English; the literal-content exception does not permit non-English explanatory prose.

## Documentation style

- Use concise, clear sentences while preserving necessary conditions, exceptions, and rationale.
- Use numbered or dash lists for enumerated requirements, conditions, examples, and categories.
- Use tables, graphs, and trees when they clarify relationships. Use Unicode box-drawing characters for directory trees.

## Prose wrapping

Keep each prose paragraph on one physical source line. Do not insert hard line wrapping to satisfy a line-width limit; let the viewer wrap the text for display.

Preserve structural line breaks for headings, separate paragraphs, list items, tables, and code blocks. The prose rule does not flatten these structures or reformat literal content.
