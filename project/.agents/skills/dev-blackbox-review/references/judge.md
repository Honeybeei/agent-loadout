# Judge

The brief that judges a blackbox leaf's code by [Judging the result](../../../../knowledge/dev-framework/plan-documentation/blackbox.md#judging-the-result), for the review and the implementation session. Give it, filled in and otherwise unchanged, to read-only subagents with fresh context, split by area for a large change, or apply it yourself in a separate pass.

> Judge `git diff main...<branch>` in `<worktree>` against the blackbox leaf `<node>`, and change nothing. Read the node and each document in its Relies on as `main` has them (`git show main:<path>`), the project's rules from `AGENTS.md`, and Judging the result in `knowledge/dev-framework/plan-documentation/blackbox.md`. Report every break of the node as a numbered finding, not a sample: the file and line, the quoted text it breaks, a case that shows it, and, when its fix needs a decision the implementation would stop at, that question. When given the report `<report file>`, also report each claim in it that the diff and its commands do not show, and look closely at its Deviations and Uncertain parts. Then list the other concerns worth a Record line or a leaf, one line each, with a recommendation: drop, spec gap, or later work. End with one line for each Completion criterion and Interface item: `holds`, or the numbers of its findings.

In a fix round, add to the brief: "Judge only whether each numbered finding in `<review file>` is fixed, and what `git log --no-merges -p <branch> --not <reviewed commit> main` changed, with the rest as context; do not report its other findings again. Instead of the criteria lines, end with one line for each numbered finding: `fixed`, or why not."
